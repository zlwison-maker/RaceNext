# Top100 MVP UI V1

Date: 2026-07-01

## Goal

This step connects the Top100 MVP sample dataset to the RaceNext frontend.

The product scope remains:

- Help runners find the most suitable next race.
- Use the existing merged local sample as the main frontend data source.
- Keep the UI lightweight, flat, and decision-oriented.

This step does not add new crawlers, source connectors, database storage, login, AI recommendation, commercial flows, image downloads, or race detail pages.

## Data Source

Primary frontend data source:

- `data/merged/merged_sample.json`

The current sample contains 40 merged records generated by the connector POC pipeline.

Frontend pages should not consume raw connector records directly. They should consume view models created by:

- `lib/raceAdapter.ts`

## View Model

`lib/raceAdapter.ts` converts `MergedConnectorRecord` into `RaceCardViewModel`.

The view model includes:

- display identity: `id`, `name`
- classification: `type`, `difficulty`, `difficultyText`
- location: `province`, `city`, `district`, `region`
- timing: `raceDate`, `month`, `dateText`, `countdownText`
- registration: `registrationStatus`, `registrationStatusText`, `registrationUrl`
- card media and metadata: `coverImage`, `categories`, `distancesText`, `elevationText`, `priceText`, `tags`
- provenance and quality: `sourceIds`, `confidence`, `summary`

Missing fields are rendered as explicit fallback text such as:

- `比赛日期待更新`
- `报名信息待更新`
- `费用待更新`
- `爬升待更新`

## Calendar UI

The calendar tab renders a filtered list of `RaceCardViewModel` records.

Supported filters:

- Type: 全部 / 马拉松 / 半马 / 越野
- Month: 全部 / months present in current data
- Region: 全部 / 华东 / 华南 / 华北 / 西南 / 西北 / 东北 / 华中
- Difficulty: 全部 / 新手友好 / 进阶 / 挑战
- Registration status: 全部 / 报名中 / 即将开放 / 已截止 / 信息待更新

`ultra_trail` is included under the 越野 filter. `high_challenge` is included under the 挑战 filter.

## Recommendation Input V1

The recommendation tab now starts with a lightweight structured input area instead of a static recommendation list.

Title:

- `你的下一场，想怎么跑？`

Subtitle:

- `选择你的目标和偏好，我们会推荐更适合你的比赛。`

Input fields:

- 当前阶段: 不限 / 新手 / 跑过半马 / 跑过全马 / 跑过越野 / 高阶跑者
- 目标赛事: dynamically filtered by 当前阶段
- 目标距离: locked by clear goals, otherwise shown as a contextual option row
- 所在地区: 不限 / 华东 / 华南 / 华北 / 西南 / 西北 / 东北 / 华中
- 报名状态偏好: 优先可报名 / 不限

Default input:

- 当前阶段: 不限
- 目标赛事: 不限
- 目标距离: 不限
- 所在地区: 不限
- 报名状态偏好: 优先可报名

There is no submit button. Any input change immediately recalculates the recommendation list on the client.

Stage-to-goal rules:

- 不限: all goals
- 新手: 不限 / 首个半马 / 风景越野
- 跑过半马: 不限 / 首个全马 / 首个越野 / 风景越野
- 跑过全马: 不限 / 首个越野 / 挑战 50K / 挑战 100K / 风景越野
- 跑过越野: 不限 / 挑战 50K / 挑战 100K / 风景越野
- 高阶跑者: all goals

When the stage changes, an illegal selected goal is automatically replaced with the first valid goal for that stage.

Target-distance rules:

- 不限 keeps the full distance-range selector visible: 不限 / ≤30KM / 30KM - 50KM / 50KM - 100KM / ＞100KM.
- 首个半马 -> ≤30KM
- 首个全马 -> 30KM - 50KM
- 首个越野 uses trail distance ranges instead of a locked fixed distance.
- 挑战 50K -> 50KM - 100KM
- 挑战 100K -> ＞100KM
- 风景越野 uses trail distance ranges: ≤30KM / 30KM - 50KM / 50KM - 100KM / ＞100KM.
- 跑过全马 + 首个越野 also uses the same trail distance ranges so the runner can choose the intended jump.

Trail distance range matching:

- ≤30KM: `distanceKm <= 30`
- 30KM - 50KM: `distanceKm > 30 && distanceKm <= 50`
- 50KM - 100KM: `distanceKm > 50 && distanceKm <= 100`
- ＞100KM: `distanceKm > 100`

The independent `是否首次越野` input has been removed. First-trail intent is inferred from 当前阶段 + 目标赛事, for example 当前阶段 is not 跑过越野 and 目标赛事 is 首个越野.

## Recommendation Rules V1

The recommendation tab remains rule-based and uses `RaceCardViewModel`.

Scoring dimensions:

- Distance match
- Race type match
- Region match
- Registration/actionability
- Difficulty fit
- Data completeness
- Future-race eligibility

Rule examples:

- Target race hard filters run before scoring:
  - `首个越野` and `风景越野`: only `trail` / `ultra_trail` races enter the recommendation pool.
  - `挑战 50K`: only `trail` / `ultra_trail` races with at least one category in `50KM - 100KM` enter the pool.
  - `挑战 100K`: only `trail` / `ultra_trail` races with at least one category in `＞100KM` enter the pool.
  - `首个全马`: only races with a `30KM - 50KM` category enter the pool.
  - `首个半马`: only races with a `≤30KM` category enter the pool.
- 不限 + 不限: recommend the most action-ready future races, prioritizing registration/source availability, clear race dates, complete distance/category information, and useful preparation windows.
- 当前阶段 not 不限 + 目标赛事 不限: recommend by current-stage fit without forcing a specific race goal.
- 当前阶段 不限 + 目标赛事 not 不限: recommend by the selected target race without requiring a declared runner stage.
- 新手 + 首个半马: prefer half marathons, beginner-friendly difficulty, action-ready records, and future races 30-180 days away.
- 跑过半马 + 首个全马: prefer marathons, intermediate difficulty, city road races, and complete registration/source information.
- 跑过全马 + 首个越野: use the selected trail distance range and prioritize elevation data.
- 跑过全马 + 挑战 100K: allow 100K trail recommendations when the runner explicitly chooses that challenge.
- 高阶跑者 + 挑战 100K: prefer 100K trail races with elevation, cutoff/category information, and registration links.
- Road-running intent is inferred from the selected distance range, for example ≤30KM for shorter road races and 30KM - 50KM for marathon-distance goals.
- 风景越野: prefer trail races with elevation and location clarity.

Match score:

- `90+`: 高度匹配
- `80-89`: 较匹配
- `70-79`: 可考虑
- Below `70`: hidden. The engine no longer backfills weak semantic matches just to reach a minimum count.

The recommendation list shows at most 10 races. If fewer than 3 strong matches exist, the page shows the matched races plus a note asking the user to loosen distance, region, or registration preferences.

Race type inference:

- Trail / ultra trail keywords are checked first.
- Multi-category road races containing a marathon-distance category are classified as `marathon` before shorter categories are considered.
- Races with only half-marathon-or-shorter categories are classified as `half_marathon`.
- Multi-category races use the highest decision-value category instead of being truncated by the shortest category.

Recommendation reasons:

- Each card generates 2-3 concrete reasons based on type, distance, region, registration/source availability, training window, and stage-goal context.
- When 当前阶段 and 目标赛事 are both 不限, reasons should avoid claiming target fit and instead explain action value, such as clearer registration information, known race date, source/registration availability, and complete distance/category data.

Risk tips:

- Half/full marathon: `请结合近期训练量、伤病情况和赛事官方关门时间，再决定是否报名。`
- Trail/ultra trail: `请重点关注累计爬升、关门时间、强制装备和近期训练量，再决定是否报名。`
- 100K: `100K 越野对训练量、装备、补给和夜间能力要求较高，请谨慎评估后报名。`

No AI recommendation, database persistence, login, or user profile storage is included in this step.

## Card Behavior

Race cards are the primary action surface.

- The entire card is clickable.
- If `registrationUrl` exists, the card opens the registration URL in a new window.
- If `registrationUrl` is missing but `sourceUrl` exists, the card opens the source page and shows `去看看`.
- If both links are missing, the card shows `信息待更新`.
- No `查看详情` button is shown.
- No detail page entry is exposed from the MVP cards.
- The legacy `/races/[slug]` route is retained only as a compatibility placeholder and returns 404.

## Known Limits

- Existing legacy mock `Race` files remain for compatibility and historical pages.
- The old race detail implementation is disabled for this MVP and does not generate static detail pages.
- Recommendation rules are intentionally simple and should be replaced only after the product has enough user and race data to justify richer ranking.
