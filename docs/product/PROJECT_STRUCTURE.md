# 下一场项目结构

## 页面结构

- `/`
  - 首页
  - 展示产品名“下一场”、slogan 和两个主要入口
  - 入口：查看赛事、获取推荐

- `/races`
  - 赛事日历
  - 数据来源：`data/races.json`
  - 支持筛选：赛事类型、月份、地区、难度等级、新手友好

- `/races/[slug]`
  - 赛事详情页
  - 从报名决策视角展示赛事信息
  - 包含 Hero、推荐理由、适合人群、不适合人群、组别信息、报名信息和数据说明

- `/recommend`
  - 赛事推荐页
  - 用户输入地区、跑者等级、目标赛事类型、目标距离、是否首次越野
  - 输出匹配度、赛事名称、赛事简介、推荐理由、难度等级、适合原因和风险提示

## 数据流

1. `data/races.json` 保存本地赛事数据。
2. `types/race.ts` 定义赛事、组别、标签、难度、地区等类型。
3. `lib/races.ts` 读取赛事数据，并提供展示用中文映射。
4. `/races` 使用 `RaceFilters` 在客户端筛选本地数据。
5. `/races/[slug]` 通过 slug 查找单场赛事并展示详情。
6. `/recommend` 使用 `lib/recommend.ts` 对赛事组别进行规则推荐。

## 推荐逻辑

推荐以组别为核心，而不是只推荐赛事主体。

能力范围规则：

- 新手推荐 L1-L4，允许挑战到 L5。
- 进阶跑者推荐 L4-L7，允许挑战到 L8。
- 高阶跑者推荐 L6-L9，允许挑战到 L10。
- 精英跑者推荐 L8-L10。

目标赛事类型规则：

- 选择越野时，只推荐越野、超级越野、UTMB。
- 选择马拉松时，优先马拉松，可次级推荐半马和路跑，不推荐越野。
- 选择 UTMB 时，只推荐 UTMB 和超级越野，不推荐公路马拉松。
- 首次越野时，优先新手友好、首越、入门和中等难度标签，并过滤 L8-L10。

MVP 推荐分为 0-100：

- 能力匹配：40%
- 赛事难度匹配：25%
- 目标距离匹配：15%
- 地理位置匹配：10%
- 标签匹配：10%
