# 1. 产品定位

MVP V2 阶段页面名称：

> RaceNext Event Service Page

中文可称为：

> 赛事参赛服务页。

本页面是 RaceNext MVP V2 阶段的唯一页面规范。

页面目标不是告诉用户：

> 你应该跑什么比赛。

而是帮助：

> 已经决定跑这场比赛的用户，完成所有参赛准备。

MVP V2 一句话：

> 帮助已经决定参加热门赛事的跑者，更高效完成报名、交通、住宿、装备和保险准备。

## Core User

核心用户：

> 已经搜索某赛事名称的高意图用户。

这些用户已经知道赛事，已经产生报名或参赛准备意图。

他们的主要问题是：

- 怎么报名？
- 报名什么时候截止？
- 住哪里方便？
- 怎么去比赛地？
- 需要带什么装备？
- 是否需要买保险？
- 有哪些报名、交通、住宿、装备和保险常见问题？

## Search Intent

典型搜索：

- 赛事名称 + 报名
- 赛事名称 + 报名时间
- 赛事名称 + 住宿
- 赛事名称 + 酒店
- 赛事名称 + 交通
- 赛事名称 + 高铁
- 赛事名称 + 装备
- 赛事名称 + 强制装备
- 赛事名称 + 保险
- 赛事名称 + 攻略

MVP V2 页面优先验证：

- 搜索流量
- 赛事服务需求
- 商业转化

不优先验证：

- AI 决策能力
- 个性化推荐能力
- 复杂赛事匹配能力

# 2. 页面信息架构

RaceNext Event Service Page 的模块顺序固定如下。

缺少真实数据的字段或模块默认隐藏。

## 1. Hero / Event Overview

目标：

> 承接 SEO 流量，让用户快速确认自己来到了正确赛事页面。

包含：

- 赛事名称
- 比赛日期
- 举办地点
- 赛事类型
- 热度信息，如果有真实数据
- 报名状态

不要展示：

- 虚构评分
- 五星评分
- 用户评分
- AI 生成难度
- 没有事实依据的热度标签

Hero 不承担复杂决策任务。

它只回答：

> 这是哪场比赛，现在是否值得继续看报名和准备信息？

## 2. 报名指南

报名指南是 MVP V2 页面最高优先级模块。

目标：

> 帮用户完成报名动作或判断报名状态。

字段：

- 报名状态
- 报名时间
- 报名截止
- 报名方式
- 报名费用
- 报名入口

数据原则：

- 字段缺失则隐藏。
- 报名入口可以是官方入口或可信报名平台，但必须如实标注。
- 不能把聚合平台或第三方报名平台误称为官网。
- 报名状态应包含信息来源或核验时间，避免误导。

## 3. 赛事核心信息

赛事核心信息保留。

目标：

> 给用户提供参赛准备所需的基础事实。

字段：

- 组别
- 距离
- 爬升
- 关门时间
- 起终点
- 比赛地点

只展示真实数据。

不要为了填充页面生成不存在的爬升、难度、关门时间、起终点信息。

## 4. 参赛准备

参赛准备是 MVP V2 页面核心商业模块。

目标：

> 把用户的参赛准备问题，连接到自然服务入口和联盟收入。

参赛准备包含四个二级模块：

- 怎么去
- 住哪里
- 带什么
- 买什么保险

### 4.1 怎么去

交通攻略。

目标：

> 帮用户判断如何到达比赛地点，并连接交通商业服务。

字段：

- 出发城市
- 推荐交通方式
- 高铁 / 飞机 / 自驾
- 到比赛地点距离
- 接驳信息
- 交通服务链接

内容原则：

- 优先提供路径判断，而不是堆砌交通工具。
- 可以按典型出发城市维护，例如北京、上海、广州、深圳、成都、杭州等。
- 对交通复杂的越野赛、景区赛、县城赛事优先补齐。
- 实时班次、实时票价不作为 MVP 必填字段。

商业入口：

- 火车票
- 机票
- 租车
- 接送服务
- 本地包车或拼车服务

### 4.2 住哪里

住宿攻略。

目标：

> 帮用户选择更合适的住宿区域，并连接酒店服务。

字段：

- 推荐住宿区域
- 推荐原因
- 距离起点 / 终点
- 价格区间
- 酒店联盟入口

原则：

- 推荐区域优先。
- 不简单罗列酒店。
- 不维护无法保证准确性的实时库存。
- 不承诺最低价。
- 优先解释为什么住这个区域更方便。

推荐区域可围绕：

- 起点附近
- 终点附近
- 领物点附近
- 高铁站附近
- 市中心
- 景区入口

商业入口：

- 携程
- 飞猪
- 美团等酒店或本地生活平台

### 4.3 带什么

装备攻略。

目标：

> 解决用户赛前准备问题，并自然连接装备购买入口。

字段：

- 官方必备装备
- 推荐装备
- 使用场景
- 装备购买入口

原则：

- 先解决准备问题，再提供购买入口。
- 官方必备装备必须来自官方信息或可信来源。
- 推荐装备必须说明使用场景。
- 不制造消费焦虑。
- 不把所有赛事都强行包装成高装备需求。

高优先级赛事：

- 越野赛
- 高海拔赛事
- 长距离赛事
- 夜间赛事
- 雨季、寒冷、炎热、山地等特殊环境赛事

商业入口：

- 淘宝联盟
- 京东联盟
- 品牌官方旗舰店或可信电商入口

### 4.4 买什么保险

保险攻略。

目标：

> 帮用户判断是否需要赛事相关保险，并连接保险服务。

字段：

- 推荐保险类型
- 适用场景
- 注意事项
- 保险入口

重点赛事：

- 越野赛
- 高海拔赛事
- 长距离赛事
- 异地参赛
- 海外参赛

内容原则：

- 推荐保险类型优先于具体保险产品。
- 必须提醒用户确认保障范围。
- 必须提醒用户确认是否覆盖马拉松、越野跑、高海拔、户外运动或赛事活动。
- 不做医疗、法律或理赔承诺。

商业入口：

- 户外运动保险
- 短期意外险
- 高风险运动扩展保障

## 5. FAQ

FAQ 是 SEO 模块。

目标：

> 覆盖用户围绕赛事准备的高频问题，并支持 FAQ Schema。

内容围绕：

- 报名
- 交通
- 住宿
- 装备
- 保险

FAQ 原则：

- 问题应贴近真实搜索。
- 答案必须基于真实信息或明确说明未知。
- 不为了 SEO 编造细节。
- 不做关键词堆砌。

## 6. 下一场推荐

下一场推荐延期。

MVP V2 不把它作为核心模块。

可以保留扩展位置，但不应影响当前页面上线。

未来进入 Decision Layer 后，再恢复：

- 同类型赛事推荐
- 同城市 / 同省份赛事推荐
- 相似难度赛事推荐
- 个性化下一场推荐

# 3. 模块优先级

## P0 - MVP V2 必须支持

- Hero / Event Overview
- 报名指南
- 赛事核心信息
- 交通
- 住宿

说明：

P0 模块直接承接搜索意图和商业转化。

没有报名、交通、住宿信息的 Event Service Page，很难完成 MVP V2 的收入验证。

## P1 - MVP V2 优先补齐

- 装备
- 保险
- FAQ

说明：

P1 模块对越野、长距离、高海拔、异地参赛赛事尤其重要。

装备和保险可以显著提高商业化深度，FAQ 可以提高搜索覆盖和页面可信度。

## P2 - 延期能力

- 下一场推荐

说明：

P2 模块可以保留产品扩展位置，但不作为 MVP V2 开发和上线前置条件。

## Future Decision Layer - 当前 MVP 不建设

- 赛事攻略
- AI 决策
- 个性化推荐
- 训练建议

说明：

这些能力属于长期 Decision Layer。

当前 MVP V2 不验证用户决策需求，不直接依赖这些模块产生商业转化，且内容生产成本较高，因此不应阻塞 Event Service Page 上线。

# 4. 数据原则

MVP V2 页面必须遵循：

> 不要为了填页面制造内容。

所有字段必须来自：

- 官方信息
- 可信来源
- 人工整理

缺失字段：

> 隐藏。

缺失模块：

> 隐藏或降级。

页面不应使用：

- 虚构评分
- 虚构热度
- AI 生成难度
- 未经核验的报名截止日期
- 未经核验的起终点
- 未经核验的官方装备
- 无来源的住宿和交通事实

商业模块允许人工维护。

人工维护内容必须：

- 与赛事事实一致。
- 能解释推荐原因。
- 可被后续复核。
- 不伪装成官方信息。

# 5. 商业化原则

页面商业入口不是广告位。

它是用户参赛路径中的自然服务。

核心原则：

- 用户先有需求，再出现服务入口。
- 服务入口服务于报名和参赛准备。
- 推荐内容必须解释使用场景。
- 联盟链接必须可追踪。
- 不用广告破坏用户完成任务的路径。

示例路径：

```text
用户需要住宿
↓
推荐住宿区域
↓
解释离起点 / 终点 / 领物点的距离
↓
酒店服务入口
```

```text
用户需要装备
↓
装备清单
↓
说明官方必备或推荐使用场景
↓
购买入口
```

```text
用户需要交通
↓
推荐到达方式
↓
说明关键距离和接驳难点
↓
交通服务入口
```

```text
用户需要保险
↓
推荐保险类型
↓
说明适用场景和注意事项
↓
保险入口
```

商业模块的判断标准：

- 是否降低用户参赛准备成本。
- 是否提高用户报名和出行确定性。
- 是否能产生可追踪点击。
- 是否能贡献联盟收入。

# 6. SEO And Distribution

MVP V2 页面优先面向中国大陆跑者。

核心流量来源：

- SEO
- 微信搜索
- 公众号

SEO 重点覆盖：

- 百度
- 微信搜索
- 搜狗
- 360 搜索

Google Search 不是 MVP V2 核心渠道。

页面应支持：

- title
- meta description
- canonical
- Open Graph
- 微信分享基础信息
- SportsEvent Schema
- FAQ Schema
- Breadcrumb Schema
- H1 / H2 / H3

页面标题和内容可自然覆盖：

- 赛事名称 + 报名
- 赛事名称 + 住宿
- 赛事名称 + 交通
- 赛事名称 + 装备
- 赛事名称 + 保险
- 赛事名称 + 攻略，仅限 FAQ 和服务型参赛准备内容可覆盖时

不做关键词堆砌。

# 7. 与旧文档关系

`RACE_DECISION_PAGE_SPEC.md` 代表 RaceNext 长期 Decision Layer 的页面规范。

MVP V2 阶段优先执行：

> `RACENEXT_EVENT_PAGE_MVP_SPEC.md`

关系说明：

- Event Service Page 是当前 MVP V2 页面。
- Decision Page 是未来长期页面。
- Monetization Layer 是当前页面核心。
- Decision Layer 是未来增强能力。
- Personalized Agent 是长期终局形态。

未来演进路径：

```text
Event Service Page
↓
Event Service Page + Light Decision
↓
Decision Page
↓
Personalized Race Decision Agent
```

当 MVP V2 验证搜索流量、赛事服务需求和商业收入后，再逐步把 Event Service Page 升级为 Decision Page。

当前 MVP V2 不承担 Decision Layer 建设。

# 8. MVP V2 Definition Of Done

一个 MVP V2 赛事页面可进入开发或上线评估前，应满足：

- 有明确赛事名称、日期、地点和赛事类型。
- 有报名状态或可信来源说明。
- 有报名入口或明确不可报名说明。
- 至少有交通或住宿中的一个 P0 商业服务模块。
- 优先补齐交通和住宿两个 P0 商业服务模块。
- 对越野、高海拔、长距离赛事优先补齐装备和保险。
- 页面没有虚构评分、AI 难度或 unsupported claims。
- 缺失字段默认隐藏。
- 商业入口是用户参赛路径中的自然服务。
