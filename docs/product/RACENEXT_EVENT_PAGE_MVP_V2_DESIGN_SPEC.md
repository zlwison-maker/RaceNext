# RaceNext Event Page MVP V2 Design Spec

Version: 1.0
Status: Active MVP V2 visual and interaction design spec
Last Updated: 2026-07-31

---

# 1. Brand Visual Positioning

RaceNext 是一个运动品牌产品。

它不是：

- 数据后台。
- SaaS 管理系统。
- 赛事数据库。
- 信息堆砌网站。
- 酒店导购网站。

RaceNext Event Service Page 的视觉方向：

> Outdoor Performance + Modern Digital Product

用户打开页面的第一感觉应该是：

> 这是一个帮助我参加比赛的专业跑者产品。

而不是：

> 这是一个查询赛事数据的网站。

参考气质：

- Arc'teryx：户外探索感、高级摄影、克制排版、专业感。
- Nike Running：强运动氛围、大图视觉、强行动按钮、能量感。
- Strava：运动数据感、训练社区气质、清晰的信息反馈。
- Apple Fitness：简洁、高级、清晰的信息层级。

关键词：

- 专业。
- 户外。
- 探索。
- 速度感。
- 高级。
- 简洁。
- 年轻。
- 有运动激情。

# 2. Design Principles

## 2.1 Sport First

页面首先要像跑者产品，而不是内容站或查询站。

视觉应传达：

- 比赛现场感。
- 目的地氛围。
- 赛前准备感。
- 行动感。

## 2.2 Decision Over Data

信息不是堆字段。

每个模块都要帮助用户做一个动作：

- 确认赛事。
- 查看报名。
- 理解基础信息。
- 选择住宿区域。
- 点击酒店平台。

## 2.3 Premium But Practical

高级感不能牺牲可用性。

页面需要：

- 大图。
- 清晰层级。
- 足够留白。
- 明确按钮。
- 快速扫描。

## 2.4 Commercial Without Ad Feeling

商业入口不能像广告。

住宿 CTA 是用户任务的一部分，不是促销 banner。

不要使用：

- 立即购买。
- 酒店优惠。
- 低价抢购。
- 官方酒店。
- 限时特价。

推荐使用：

- 查看附近酒店。
- 查看住宿选择。
- 查看该区域酒店。

# 3. Page Layout

页面必须 Mobile First。

核心结构：

```text
Hero
↓
报名指南
↓
赛事核心信息
↓
参赛住宿指南
↓
FAQ
↓
下一场推荐
```

整体节奏应接近运动品牌官网：

```text
大图
↓
核心信息
↓
行动入口
↓
内容展开
```

每个模块不能只是简单卡片堆叠。

页面应有视觉节奏：

- Hero 负责情绪和赛事识别。
- 报名指南负责行动。
- 赛事核心信息负责确认事实。
- 住宿指南负责商业转化。
- FAQ 负责搜索长尾和降低疑虑。
- 下一场推荐低调收尾。

---

# 4. Hero Design

Hero 是第一视觉重点。

目标：

> 让用户产生“我要参加这场比赛”的感觉。

Hero 包含：

- 赛事主视觉图片。
- 赛事名称。
- 日期。
- 地点。
- 类型。
- 报名状态。

## 4.1 Visual Treatment

不要做普通 Banner。

Hero 应接近运动品牌赛事宣传页：

- 大面积赛事图片。
- 文字覆盖。
- 强视觉冲击。
- 画面有速度、山野、城市赛道或比赛氛围。
- 保证文字可读。

可以使用：

- 深色渐隐覆盖保证文字对比。
- 大号赛事名称。
- 简洁元信息。
- 明确报名状态标签。

不要使用：

- 后台标题栏。
- 纯白标题区。
- 过度信息密集的首屏。
- 虚构热度和评分。
- 与赛事无关的抽象插画。

## 4.2 Content Hierarchy

层级：

1. 赛事名称最大。
2. 日期和地点次之。
3. 类型、距离、报名状态作为辅助信息。

移动端首屏应至少完成：

- 赛事识别。
- 当前状态理解。
- 继续向下查看报名或住宿的动机。

# 5. Module Visual Specs

## 5.1 报名指南

报名指南不要设计成后台信息表。

它应该像比赛准备步骤。

推荐结构：

```text
报名状态
↓
报名时间 / 截止
↓
报名入口
```

视觉要求：

- 使用轻量信息展示。
- 状态明确。
- 主行动按钮醒目。
- 内容少而准。
- 缺失字段隐藏。

避免：

- 多列表格。
- 复杂字段矩阵。
- 灰色后台面板。
- 无重点的说明文字。

## 5.2 赛事核心信息

赛事核心信息不要做字段列表。

它应是赛事数据视觉化模块。

展示：

- 距离。
- 日期。
- 地点。
- 起点。
- 终点。
- 爬升，如果有。
- 组别。

视觉参考：

- Apple Fitness 的数据展示感。
- Strava 的运动数据块。

设计要求：

- 数字和单位有清晰层级。
- 每个数据点可快速扫描。
- 移动端使用紧凑单列或双列。
- 桌面端可形成运动数据带。

不要：

- 普通字段列表。
- 密集表格。
- 小字号堆叠。
- 过多边框。

## 5.3 FAQ

FAQ 应轻量、清晰、利于 SEO。

设计要求：

- 使用可展开问题结构。
- 问题文案贴近搜索语言。
- 视觉不要抢住宿模块。
- 不写成长篇攻略文章。

## 5.4 下一场推荐

下一场推荐是长期增长入口。

MVP 阶段应低调展示。

设计要求：

- 不抢主 CTA。
- 不干扰住宿商业路径。
- 可使用简单横向或列表推荐。
- 不使用复杂个性化语言。

# 6. Accommodation Commercial Module Design

模块名称：

> 参赛住宿指南

定位：

> 赛事住宿决策。

目标：

> 帮助用户快速判断“我应该住哪里？”

不要设计成：

- 酒店列表。
- 酒店价格页。
- 酒店评分页。
- 酒店评论页。
- 酒店导购聚合页。

## 6.1 Module Role

住宿模块是 MVP 商业核心。

但它不是广告区。

它应该像一个专业跑者给出的赛前住宿建议。

用户路径：

```text
理解赛事地点
↓
选择住宿区域
↓
点击查看附近酒店
```

## 6.2 Area Recommendation Card

区域推荐卡应该像运动建议卡，而不是广告卡。

每个区域卡包含：

- 区域名称。
- 推荐类型：距离优先 / 交通优先 / 性价比优先 / 综合推荐。
- 距赛事地点。
- 交通便利程度。
- 价格水平。
- 适合用户。
- 推荐理由。
- CTA。

示例：

```text
起点附近
距离优先

适合：第一次参赛 / 冲成绩

比赛当天减少移动风险，适合希望赛前通勤更确定的跑者。

[查看附近酒店]
```

视觉要求：

- 高级推荐卡。
- 留白充足。
- 标签清晰。
- CTA 明确。
- 不像广告。
- 不像酒店平台列表项。

MVP 限制：

- 每场赛事最多 3 个区域卡。
- 不展示酒店名称。
- 不展示酒店实时价格。
- 不展示酒店评分。
- 不展示用户评论。

## 6.3 Suggested Card Types

区域卡类型：

- 距离优先：适合第一次参赛 / 冲成绩。
- 交通优先：适合外地跑者 / 家属同行。
- 性价比优先：适合预算有限。
- 综合推荐：RaceNext 默认推荐。

不同类型应用不同微文案和视觉提示，但不要使用过多颜色。

# 7. CTA Design

所有商业入口必须保持 RaceNext 品牌调性。

CTA 不要有广告感。

禁止文案：

- 立即购买。
- 酒店优惠。
- 低价抢购。
- 官方酒店。
- 限时特价。
- 今日最低价。

推荐文案：

- 查看附近酒店。
- 查看住宿选择。
- 查看该区域酒店。

CTA 设计要求：

- 行动明确。
- 触控面积足够。
- 与推荐理由相邻。
- 移动端按钮足够大。
- 桌面端可在卡片底部固定。
- 不使用闪烁、强促销、夸张标签。

CTA 层级：

1. 主 CTA：查看附近酒店。
2. Provider 入口：携程 / 美团 / 飞猪。
3. FAQ 文本入口：可选，弱化展示。

# 8. Color System

避免纯黑白灰。

需要运动感，但保持高级和克制。

建议方向：

- 岩石灰。
- 森林绿。
- 山野蓝。
- 沙土色。
- 雾白。
- 暖橙或能量红作为少量强调色。

## 8.1 Base Colors

基础色用于页面背景、正文和模块区分：

- 岩石灰：专业、克制。
- 雾白：干净、呼吸感。
- 深石墨：文字主色。
- 沙土色：户外温度。

## 8.2 Accent Colors

强调色用于 CTA、状态和关键动作：

- 能量橙。
- 跑道红。
- 山野蓝。
- 森林绿。

规则：

- 一个页面最多使用 1 个主强调色。
- 强调色主要用于 CTA 和关键状态。
- 不使用大面积彩虹渐变。
- 不做花哨旅游网站色彩。

## 8.3 Status Colors

报名状态可使用克制色彩：

- 报名中：绿色或能量橙。
- 待开放：山野蓝或中性色。
- 已截止：岩石灰。
- 待确认：沙土色或中性色。

状态颜色不能压过 Hero 和 CTA。

# 9. Typography And Spacing

字体方向：

> 现代无衬线字体。

字体气质：

- 清晰。
- 年轻。
- 运动。
- 专业。

层级：

1. 赛事名称最大。
2. 模块标题其次。
3. 数据数字可以放大。
4. 正文简洁。
5. 辅助说明低调。

## 9.1 Typography Rules

不要：

- 小字号密集信息。
- 长段落。
- 负字距。
- 多种字体混用。
- 过度装饰标题。

建议：

- Hero 标题有冲击力。
- 数据数字更醒目。
- 模块标题简短。
- 正文行长适中。
- 移动端保证可读。

## 9.2 Spacing Rules

页面需要大量留白。

模块之间要有呼吸感。

住宿区域卡内部：

- 标题和标签紧密关联。
- 推荐理由留足阅读空间。
- CTA 与正文保持清晰关系。

不要：

- 信息拥挤。
- 卡片套卡片。
- 大量边框切割。
- 模块之间距离过近。

---

# 10. Responsive Design

页面必须 Mobile First。

## 10.1 Mobile

重点：

- 单列布局。
- 大图片。
- 大按钮。
- 卡片纵向排列。
- 快速浏览。
- 适合微信内打开。

移动端设计要求：

- Hero 使用大图。
- 赛事名称必须清楚可读。
- 报名按钮容易点击。
- 住宿模块不能埋太深。
- 区域卡片单列。
- CTA 大而明确。
- FAQ 可折叠。
- 避免复杂表格。

## 10.2 Desktop

桌面端可以：

- 大图 Hero。
- 双栏布局。
- 住宿区域横向展示。
- 右侧轻量快捷导航。

但不要：

- 桌面后台布局。
- 大量表格。
- 复杂筛选器。
- 管理系统侧栏。
- 数据看板风格。

桌面端应像：

> 运动品牌赛事页面。

而不是：

> 赛事数据库后台。

---

# 11. Forbidden Design Directions

禁止方向：

- 黑白后台风。
- 表格感。
- ERP 感。
- SaaS 管理系统感。
- 信息门户感。
- 赛事数据库感。
- 酒店导购网站感。
- 低质旅游网站感。
- 过度卡片化。
- 大量边框。
- 大量广告 banner。
- 酒店价格比较页。
- 酒店评分点评页。
- 泛攻略长文页。

禁止视觉元素：

- 虚构星级评分。
- 虚构用户评分。
- 无来源热度标签。
- 酒店促销角标。
- 低价抢购标签。
- 闪烁或强促销 CTA。
- 大面积纯黑白灰。

---

# 12. Final Design Goal

RaceNext Event Service Page 最终应该看起来像：

> 一个现代运动品牌产品。

而不是：

> 一个赛事数据库后台。

页面应让用户相信：

- RaceNext 懂跑者。
- RaceNext 懂比赛。
- RaceNext 懂赛前准备。
- RaceNext 能帮我更快完成报名和住宿决策。

MVP V2 的设计成功标准：

- 用户能快速确认赛事。
- 用户能快速找到报名入口。
- 用户能看到并理解住宿建议。
- 用户愿意点击“查看附近酒店”。
- 页面整体有专业、户外、现代、运动品牌的气质。
